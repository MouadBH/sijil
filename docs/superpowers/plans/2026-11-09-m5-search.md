# M5 Search and Ask Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Field and full-text search with saved views and tags (ARC-1), natural-language questions over the archive answered by the in-region model with citations and with sums computed in code (ARC-2), and learning from corrections (REC-5).

**Architecture:**
- Every workspace's index database gains a denormalised `search_doc` row per live document: state, dates, type, supplier, amounts, tags and the normalised OCR text, plus a `tsvector` and trigram indexes. Search is one SQL query there, filters and text together.
- Embeddings are per-document chunks in the same index database (pgvector), computed by `worker-extraction` with an Ollama embedding model.
- Ask is asynchronous. `POST /ask` records the question and a new `worker-ask` answers it:
  1. the model turns the question into a structured intent;
  2. code computes any sum from the stored field values (`Decimal`);
  3. hybrid retrieval picks the cited documents;
  4. the model writes the sentence around the computed figure;
  5. a validator checks the figure and the citations.
- Corrections feed a per-workspace `supplier` table, Paperless correspondents with matching rules, and extraction hints.

**Tech Stack:** Postgres 16 full text (`simple` configuration plus `unaccent`) and `pg_trgm`; pgvector (HNSW, cosine); Ollama `/api/embed` with `bge-m3` (1024 dimensions, multilingual including Arabic) and `/api/chat` with `qwen3:4b` (already used for extraction); FastAPI, SQLAlchemy 2 async, Celery.

**Spec:**
- `SPEC.md`: ARC-1, ARC-2 and REC-5; NFR performance "search results in < 500 ms at p95 for 100k documents".
- Amended by `docs/superpowers/specs/2026-10-31-sijil-mvp-design.md` §5.3 ("Ask", "Learning") and §5.5 (OCR-derived text and embeddings live in the per-workspace index database).
- `docs/plan.md`: Milestone 5, tasks 5.1–5.4.

**Product-owner decision for M5 (2026-11-09):** full-text search runs in our index database, not in Paperless. Paperless stays the OCR engine and the working copy. This deviates from SPEC's "Paperless for search" and from docs/plan.md 5.1 "full text through Paperless".

## Global Constraints

- **Paperless-ngx is unmodified.** The image is `ghcr.io/paperless-ngx/paperless-ngx:3.4.1`, configured only by environment variables, reached over REST from `services/` only, and only through `sijil_core.paperless`. Search and Ask never call Paperless at request time.
- **No JS package talks to Paperless.**
- **Region.**
  - Every service requires `SIJIL_REGION`.
  - Every workspace-scoped request and job calls `sijil_core.region.assert_region` before it reads or writes anything of the workspace.
  - AI calls go to the compose `ollama` service only, through `sijil_core.ollama.OllamaClient` (its host allowlist).
  - No question, answer, OCR text or embedding leaves the region.
- **Where content lives.** OCR text, embeddings, questions, answers, saved-view filters, tags and supplier records are all document content or derived from it, so they all live in the workspace's index database. None goes in the shared control-plane database.
- **Retention lock** (four layers, unchanged):
  - Tags and Ask records are annotations: they never change a sealed field value, `fields_sha256` or the original.
  - `index.purge_document` must also delete every new per-document table's rows (`search_doc`, `doc_chunk`, `document_tag`), under the same gate.
  - Every new path that can change or delete document data gets a test in `tests/retention/`.
- **Terminal documents are invisible.** Search, Ask retrieval, aggregates and suggestions never return or count a document in `removed`, `deleting` or `deleted`.
- **Audit.** Append-only and hash-chained. Audit `data` is str, int, bool or None, and never carries query text, question text, answer text, field values or tag names. It may carry counts, filter names and kinds (ruling P5).
- **Machine codes, never prose.**
  - The API returns machine codes. Ask returns the model's answer text, which is generated content.
  - Every fallback sentence is a key the client renders from `packages/i18n/messages/{fr,ar,en}.json`. Add the keys in all three languages, with ICU plurals where counts appear.
  - New codes:
    - `search.query_invalid` 422;
    - `search.view_not_found` 404;
    - `ask.not_found` 404;
    - `ask.question_invalid` 422;
    - `ask.unavailable` 503 (the model or the index is down);
    - `tag.invalid` 422.
- **Money is `Decimal`** in Python, a string in JSON. Sums are computed in SQL over `numeric` or in Python `Decimal`, never by the model and never in float.
- **Shared code.** It goes in `sijil_core`. Never import `sijil_cp` from the worker or the reverse.
- **Tooling.** Python 3.13, ruff (line length 100), `mypy --strict`, pytest `asyncio_mode=auto`. TDD: each test is seen failing first. Conventional Commits, small. SAMPLE fixtures only.
- **Index schema.** It moves from `SCHEMA_VERSION = 2` to `3` (and to `4` if a later task needs it) through the existing `ensure_schema` path.
- **Mark model-bound tests `@pytest.mark.slow`.** Mark the 100k-document perf test `slow` too.

## Review Focus

1. **A document removed, deleted or edited after it was indexed.**
   - The next search or Ask never returns a removed or deleted document, and never counts it in a sum.
   - A field edit or a correction note shows its effective value in search and in sums within the same request that made it: the `search_doc` row is updated in the same index transaction, with no eventual-consistency window.
2. **Arabic and mixed-script search.**
   - An Arabic query matches Arabic text regardless of `ـ` tatweel, `أ/إ/آ` → `ا`, `ى` → `ي`, `ة` → `ه`, and Arabic-Indic digits, on both sides.
   - A French query matches regardless of accents and case.
   - A 15-digit ICE or an invoice number matches exactly.
3. **The model is wrong or hostile.**
   - The question parser returns a supplier that doesn't exist, a period in the future, or malformed JSON. The answer then degrades to "no matching documents" (code `ask.no_match`) or a lookup, and never invents a figure.
   - The writer model changes the computed figure or cites an id it wasn't given. The validator then replaces the text with the templated answer (an i18n key plus the figure), and the citations remain the retrieved ones.
   - A document whose text says "ignore your instructions" can't make Ask cite documents outside the retrieval set, or report a figure other than the computed one.
4. **Sums over mixed states and currencies.**
   - A sum covers `filed` and `sealed` documents, not `needs_review`, and says how many were left out.
   - Corrected values replace sealed ones.
   - Amounts in different currencies are never added together: there is one figure per currency.
   - A period means the retention basis date, as for exports.
5. **Search at scale, and paging.**
   - 100k `search_doc` rows: a filtered text query answers in < 500 ms at p95, measured server-side in the API.
   - Keyset cursors don't skip or repeat rows when a new document arrives between pages.
   - Sorting by date and by amount is stable on ties (`ledger_id` tiebreak).

If the index-database owner can't run `CREATE EXTENSION`, provisioning creates them with the role that creates the database. Existing workspaces get them through the same upgrade path; say which path you used.
    - Table `search_doc`:
      - `ledger_id` uuid PK;
      - `state` text NOT NULL;

      - `document_type` text;

      - GIN on `tsv`;
      - GIN trigram on `supplier_name` and on `content`;
      - btree on `(basis_date, ledger_id)`, `(total_ttc, ledger_id)`, `(state)`, `(document_type)` and `(supplier_ice)`;
      - GIN on `tags`.
    - Table `document_tag`: `ledger_id`, `tag` text CHECK `char_length BETWEEN 1 AND 50`, `created_by`, `created_at`, PK `(ledger_id, tag)`.
    - The purge gate (`sijil.purge`) is the only DELETE path for `search_doc` and `document_tag`. Task 3 adds `doc_chunk`. `purge_document` deletes all of them.
  - `def search_normalise(s: str) -> str` in `text.py`. It applies `normalise`, then:
    - casefolds;
    - strips Latin accents (NFKD, drops combining marks);
    - removes Arabic tatweel `ـ` and harakat (U+064B–U+0652);
    - maps `أ إ آ ٱ` → `ا`, `ى` → `ي`, `ة` → `ه`;
    - maps Arabic-Indic `٠–٩` and Persian `۰–۹` digits → ASCII.

    Queries are normalised with the same function, so both sides match.
  - `async def upsert_search_doc(conn, ledger: SearchLedgerFacts, fields: FieldsRow | None, corrections: list[Correction], content: str | None) -> None`.
    - `SearchLedgerFacts` is a small dataclass: `ledger_id`, `state`, `ingested_at`, `region` and `now`, so callers pass ledger facts without importing ORM rows across packages.
    - Values are the effective ones (`index.effective_fields`); `corrected` lists the corrected names.
    - `basis_date` is `retention_basis(date, ingested_at, region, now)`.
    - `content=None` keeps the stored content.
    - Upserting a terminal state deletes nothing: it is refused (`ValueError`). Terminal rows leave only through the purge.
  - Upkeep, each in the same index transaction as the change it reflects:
    - ingest at `consumed`: state, ingested_at, empty content;
    - extraction after `_route`: the normalised Paperless content, which extraction already reads, plus fields and the routed state;
    - PATCH fields, seal and correction: the CP's existing index transaction.
  - A removal or deletion leaves the row until `purge_document`. Meanwhile the removal handler (`api/removal.py`) and approve-deletion (`api/retention.py`) set its `state` to `removed` or `deleting` right after their commit, and Task 2's query excludes terminal states. If that update fails, `search_resync` fixes it. The purge then deletes the row.
  - `sijil.search_resync()` runs daily per active workspace in the region. It compares `search_doc.state` with the ledger, fixes mismatches and creates missing rows: content is fetched from Paperless once (`document_content`), fields from `document_fields`. It audits `search.resynced` with `{fixed: int}` when the count is above 0.
  - `sijil.search_backfill(workspace_id)` does the same for every live row. A CLI `sijil-cp search backfill <workspace_id>` enqueues it. `make seed` runs it for the SAMPLE workspace.

- Produces:
  - `SearchFilters` (pydantic, `extra="forbid"`):
    - `q: str | None` (at most 200 characters);
    - `document_type: list[str]`;
    - `supplier: str | None` (an ICE when 15 digits, else a name);

  - `def build_search(filters, sort, cursor, limit) -> Select`.
    - Sort is one of `relevance`, `date_desc`, `date_asc`, `amount_desc` or `amount_asc`, with a keyset cursor whose tiebreak is `ledger_id`.
    - `q` matching:
      - a 15-digit token matches `supplier_ice` exactly;
      - a token matching `^[A-Za-z0-9/_-]{3,}$` also matches `number` exactly;
      - the rest is `websearch_to_tsquery('simple', search_normalise(q))` against `tsv`, OR trigram similarity on `supplier_name` above 0.3.
    - Relevance is `ts_rank_cd` plus similarity.
  - `POST /v1/workspaces/{id}/search` with body `{filters, sort, cursor?, limit≤100}`.
    - Permission `documents_read`.
    - Returns `{items: [{id, state, document_type, basis_date, supplier_name, number, total_ttc, currency, tags, corrected, snippet}], next_cursor}`.
    - `snippet` is `ts_headline` over `content`, at most 200 characters, with no HTML: `«` and `»` mark the hits.
    - Audits `search.performed` with `{result_count, filters: "q,document_type,…"}`: the names of the filters used, never their values.
  - Saved views in the index database: table `saved_view` with `id` uuid, `name` text (1–80 characters), `filters` jsonb, `sort` text, `created_by` uuid, `created_at`, `updated_at`.
    - `GET`, `POST`, `PUT` and `DELETE /v1/workspaces/{id}/search/views[/{view_id}]`.
    - `documents_read` to list them. Creating them needs `documents_read` too. Editing or deleting needs the creator, or Owner or Admin.
    - Each change audits `search.view_changed` with `{op}`.
  - Tags:
    - `PUT /v1/workspaces/{id}/documents/{doc_id}/tags` with body `{tags: [str]}`, replacing the set.
    - Each tag is trimmed, casefolded and 1–50 characters, at most 20 per document; a bad tag is 422 `tag.invalid`.
    - Permission `documents_review`.
    - Allowed on sealed documents: tags are annotations. A terminal state answers 409 `document.not_reviewable`.
    - It updates `document_tag` and `search_doc.tags` in one index transaction, and audits `document.tagged` with `{count}`.

  - `infra/compose/docker-compose.yml` (`worker-ask`), `infra/scripts/smoke.sh`;
  - `packages/i18n/messages/{fr,ar,en}.json`: fallback answer keys `ask.answer.sum`, `ask.answer.count`, `ask.answer.lookup`, `ask.answer.no_match`, `ask.answer.excluded`, with ICU plurals.
- Test: `libs/sijil-core/tests/test_ask_intent.py`, `services/worker/tests/test_ask.py`, `services/control-plane/tests/test_ask_api.py`, `tests/integration/test_ask_model.py` (slow)

**Interfaces:**
- Consumes: Task 2's `build_search` and `SearchFilters`; Task 3's `doc_chunk` and `OllamaClient.embed`; Task 5's `supplier` table if present (Ask falls back to `search_doc.supplier_name` matching).
- Produces:
  - `POST /v1/workspaces/{id}/ask`, body `{question: str (3–500 chars), locale: "fr"|"ar"|"en"}`.
    - Permission `documents_read`.
    - It writes an `ask_query` row in the index database and audits `ask.asked` with `{locale}`. After the commit it enqueues `sijil.answer_question` on the queue `ask`.
    - It returns 202 `{id, state: "queued"}`.
    - Questions are limited to 20 per user per minute (Redis), else 429 `ask.rate_limited`.
  - `GET /v1/workspaces/{id}/ask/{ask_id}` returns:
    ```
    {id, state: queued|answering|answered|failed, locale,
     answer_text: str | null,
     answer_code: str | null,
     figures: [{measure, value: "1234.50", currency, document_count}],
     excluded: {needs_review: int},
     citations: [{id, supplier_name, basis_date, total_ttc, currency}],
     error_code}
    ```
    - `answer_code` is set when the text is templated: the client renders the i18n key with the figures.
    - Only the asker, or an Owner or Admin, can read it; anyone else gets 404 `ask.not_found`.
  - `ask_query` (index database): `id`, `question`, `locale`, `state`, `intent` jsonb, `answer_text`, `answer_code`, `figures` jsonb, `citations` uuid[], `excluded` jsonb, `error_code`, `created_by`, `created_at` and `answered_at`. Questions are kept 90 days, then a daily task deletes them; the table has no lock trigger, since it is not document data.
  - Intent (`ask_intent.py`): a JSON schema the model must fill:
    ```
    {"kind": "sum"|"count"|"lookup",
     "measure": "vat"|"total_ttc"|"total_ht"|null,
     "supplier": str|null,
     "document_type": one of DOCUMENT_TYPES|null,
     "period_from": "YYYY-MM-DD"|null, "period_to": "YYYY-MM-DD"|null,
     "keywords": str|null}
    ```
    `validate_intent(raw, today) -> Intent`:
    - drops unknown keys;
    - turns a bad date or an inverted or future period into null bounds;
    - requires a `measure` for `sum`;
    - degrades a `sum` with no measure to `lookup`;
    - truncates `keywords` to 200 characters.
  - `sijil.answer_question(ask_id, workspace_id)` runs in `worker-ask`: queue `ask`, concurrency 1, networks `core` and `ai`, no tenant network, no Docker socket, holding only the region, the DB URL, the master key (to open index databases) and the Ollama settings. The steps:
    1. Assert the region.
    2. **Intent.** One `chat_json` call (temperature 0, `think: false`) with the question, the locale, today's region-local date and the intent schema, then `validate_intent`.
    3. **Supplier.** Resolve it against the `supplier` table (Task 5) or `search_doc.supplier_name`: trigram similarity at least 0.4, the best match, a 15-digit ICE exact. If none is found, the answer is `ask.answer.no_match`.
    4. **Figures.** For `sum` or `count`, one SQL aggregate over `search_doc` rows in state `filed` or `sealed` that match the intent's filters, grouped by `currency`: `sum(<measure>)` as `numeric`, and `count(*)`. `excluded.needs_review` counts the matching `needs_review` rows. Values are serialised from `Decimal` with exactly 2 decimals.
    5. **Retrieval.** `build_search` with the same filters plus `keywords` as `q`, top 20. Re-rank with chunk embeddings: cosine distance between the question's embedding and each candidate's best chunk; combined score = 0.5 × normalised text rank + 0.5 × (1 − distance). Keep the top 8. For `sum` or `count`, the citations are the documents that make up the figure, up to 20, ordered by amount descending.
    6. **Writer.** One `chat_json` call returning `{answer: str}`, given the locale, the question, the figures (as strings), the citation ids each with a short fields line, and at most 3 snippets of at most 300 characters from the retrieved content. The system prompt says: answer only in `<locale>`; use only the given figures; cite only the given ids in the form `[#n]`.
    7. **Validator.**
       - Every figure value must appear in the answer after normalising digits (`search_normalise` maps Arabic-Indic digits; accept `1 234,50`, `1,234.50`, `1234.50` and `1234,50`).
       - Every `[#n]` must refer to a given id.
       - For `ar`, the answer must contain Arabic script; for `fr` or `en`, it must be Latin script.
       - Otherwise set `answer_text = null` and `answer_code` to the matching `ask.answer.*` key.
    8. Store the result and audit `ask.answered` with `{kind, citation_count, templated: bool}`.

    Ollama is unavailable after the M3 retry window: the state is `failed`, `error_code` is `ask.unavailable`, and the audit is `ask.failed` with `{code}`.
  - Compose `worker-ask` mirrors `worker-extraction`'s settings shape (`AskSettings`, entrypoint `sijil_worker.main_ask`). Smoke checks that it has no tenant network, no Docker socket, and none of the seal, removal or export keys.

# M1 Tenancy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A person signs up, enrols TOTP, creates a business organisation, and within 3 minutes its workspace is `active`, with its own Paperless-ngx container, network, Redis, databases and encrypted service token. Everything is driven by the `/v1` API.

**Architecture:**
- SQLAlchemy models live in `sijil_core.db`, so the control plane and worker share them without importing each other. Alembic migrations stay in the control plane and run as the owner role.
- The control plane does auth, sessions, CSRF, TOTP, permissions and org/workspace APIs, and enqueues provisioning with Celery `send_task`.
- The worker runs `provision_workspace` through a `TenantRuntime`. `DockerRuntime` is the dev implementation.
- Secrets are sealed with envelope encryption under a per-workspace key derived from the regional master key.

**Tech Stack:**
- Control plane: FastAPI, SQLAlchemy 2 (async, asyncpg), Alembic.
- Auth and crypto: argon2-cffi, pyotp, cryptography (AES-256-GCM, HKDF).
- Infra clients: redis, docker (Python SDK), httpx.
- Tests: pytest, respx.

**Spec:** `SPEC.md`, as amended by `docs/superpowers/specs/2026-10-31-sijil-mvp-design.md` (§5.1 auth, §5.2 tenant runtime, §5.7b region). Parent plan: `docs/plan.md` (M1 table).

## Global Constraints

- Everything in `docs/plan.md` § Global Constraints applies.
- Error responses are always `{"error": {"code": "<machine.code>"}}`, never prose. Codes used in M1:

| Code | Status |
| --- | --- |
| `auth.invalid_credentials` | 401 |
| `auth.unauthenticated` | 401 |
| `auth.rate_limited` | 429 |
| `auth.csrf` | 403 |
| `auth.totp_required` | 401 |
| `auth.totp_invalid` | 401 |
| `auth.totp_enforced` | 409 |
| `auth.totp_enrolment_required` | 403 |
| `auth.step_up_required` | 403 |
| `auth.weak_password` | 422 |
| `user.email_taken` | 409 |
| `org.region_immutable` | 409 |
| `org.type_unsupported` | 422 |
| `org.workspace_limit` | 409 |
| `org.last_owner` | 409 |
| `member.forbidden_role` | 403 |
| `member.user_not_found` | 404 |
| `region.mismatch` | 421 |
| `not_found` | 404 |
| `forbidden` | 403 |

- Passwords: argon2id (`argon2-cffi` defaults), length 12–128.
- Sessions:
  - Cookie `sijil_session`: `HttpOnly; Secure; SameSite=Lax; Path=/`.
  - The token is 32 random bytes, base64url. Only its SHA-256 is stored.
  - Sessions expire after 12 h absolute or 2 h idle. `last_seen_at` is written at most once a minute.
  - A new token is issued on login and again after TOTP verification (no session fixation).
- CSRF: double-submit. The cookie `sijil_csrf` is not HttpOnly; every unsafe method must send the header `X-CSRF-Token` with the same value, and that includes login and signup. `GET /v1/auth/csrf` issues the cookie.
- Login rate limit: 10 failures per (lower-cased email, IP) per 15 min, in Redis.
- TOTP:
  - Implemented with `pyotp`: 30 s step, 6 digits, `valid_window=1`. A time-step that has already been used is rejected.
  - 10 recovery codes per user, each 10 base32 characters, stored as HMAC-SHA256 keyed by `HKDF(master, info=b"sijil:recovery-codes")`, single use.
  - Step-up = `session.totp_verified_at` within the last 10 minutes.
- Crypto:
  - AES-256-GCM.
  - Per-workspace key-encryption key = `HKDF-SHA256(master_key, salt=None, info=b"sijil:kek:" + key_id)`.
  - The data key is 32 random bytes, wrapped by the KEK with AAD = `key_id`.
  - The payload is sealed with AAD = the caller's context string. Format `Envelope.to_bytes()`: `b"SJE1" | u16 len(key_id) | key_id | u16 len(wrapped) | wrapped | 12-byte nonce | ciphertext`.
- Region:
  - Country → region map `{"MA": "ma-cas"}`.
  - Creating an organisation whose region ≠ `SIJIL_REGION` → `421 region.mismatch`.
  - Every workspace route asserts the region.
- Roles: `owner`, `admin`, `member`, `readonly`. The Auditor guest is R2. The effective role in a workspace = the higher of the org-level and workspace-level membership.
- Only `type="business"` organisations are accepted (one workspace each). `firm` stays in the enum, and the API answers `422 org.type_unsupported`.
- The Paperless service user gets view/add/change and **never** any `delete_*` permission. The support user gets `view_*` only.
- New settings (all required, no defaults):
  - `SIJIL_MASTER_KEY`: base64 of exactly 32 bytes.
  - `SIJIL_COOKIE_SECURE`: bool.
  - Worker only: `SIJIL_PROVISIONER_DATABASE_URL`, `SIJIL_TENANT_IMAGE`, `SIJIL_COMPOSE_PROJECT`, `SIJIL_TESSDATA_VOLUME`.
- DB tests use a throwaway database with an owner role and an app role, mirroring production grants. Tests never connect as superuser except to create and drop that database.

## Review Focus

1. **Email case and whitespace:** ` Mouad@Example.COM ` and `mouad@example.com` are the same account, for signup, login and adding members. → Task 1 `test_email_unique_case_insensitive`, Task 4 `test_login_email_normalised`.
2. **Account enumeration:** an unknown email and a wrong password return the same `401 auth.invalid_credentials`, and both run one argon2 verify. → Task 4 `test_unknown_email_and_wrong_password_indistinguishable`.
3. **Two signups with the same email at once:** one gets 201, the other `409 user.email_taken`, never a 500. → Task 4 `test_concurrent_signup_same_email`.
4. **A TOTP code replayed in the same 30 s window:** rejected. → Task 5 `test_totp_code_cannot_be_reused`.
5. **Provisioning that crashes halfway and is retried:** the retry finishes without duplicating databases, containers or users, and reuses stored secrets. → Task 8 `test_provision_is_idempotent_on_retry`.

    8. `workspace.paperless_url = handle.url`, state `active`, job `succeeded`.

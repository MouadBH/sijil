# M2 Capture and Ledger Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every file that reaches a workspace is accepted in under 2 s. That covers web upload (CAP-2) and the workspace's inbound email address (CAP-1). Each file is:
- hashed with SHA-256;
- written once to object-locked in-region storage;
- recorded in the document ledger, with exact duplicates refused (CAP-4);
- logged in a per-workspace hash-chained audit log (ARC-4);
- pushed into the workspace's own Paperless-ngx.

A nightly drift check flags any original that changed or vanished in Paperless.

**Architecture:**
- **Shared ingest path.** `sijil_core.ingest.accept_file` is the one entry point, used by the control plane's upload route and by the worker's SMTP receiver. It streams to a spool file while hashing and size-checking, sniffs the type, puts the original into the object store (GOVERNANCE lock), inserts the ledger row (unique per workspace + SHA-256), appends an audit event, and enqueues `sijil.ingest_document`.
- **Worker.** It reads the original back from the object store, posts it to Paperless with the service token, and polls the task.
- **Audit chain.** `sijil_core.audit.append` serialises with a per-workspace advisory lock.
- **No document content in the shared database.** No filenames, subjects or senders go into it; Paperless and the object store hold them.

**Tech Stack:** FastAPI streaming uploads (`python-multipart`), boto3 (in threads) against RustFS 1.0.4, aiosmtpd, Celery beat, asyncpg/SQLAlchemy, Docker SDK.

**Spec:** `SPEC.md`, as amended by `docs/superpowers/specs/2026-10-31-sijil-mvp-design.md` (§5.2a object store, §5.4 retention, §5.5 ledger and audit, §5.7 capture). Parent plan: `docs/plan.md` (M2 table). Backlog: `docs/backlog-m1.md` ("First M2 task").

## Global Constraints

- Everything in `docs/plan.md` § Global Constraints, and in the M1 plan's Global Constraints (error envelope, codes, sessions, CSRF, roles, region), still applies.
- **New error codes:**

| Code | Status | Meaning |
| --- | --- | --- |
| `upload.too_large` | 413 | over 100 MB, i.e. 104,857,600 bytes |
| `upload.unsupported_type` | 415 | sniffed type not on the allow-list |
| `upload.empty` | 422 | zero-byte file |
| `document.duplicate` | 409 | body also carries `"document_id": "<existing ledger id>"` |
| `document.not_found` | 404 | |
| `workspace.not_ready` | 409 | upload into a workspace whose state is not `provisioning` or `active` (final-review ruling I1) |
| `engine.unavailable` | 200 | flag inside list responses, never an error status |

- **Upload allow-list** (decided by content sniffing, never by extension or client `Content-Type`):

| Format | Rule |
| --- | --- |
| PDF | starts with `%PDF-` |
| JPEG | `FF D8 FF` |
| PNG | `89 50 4E 47 0D 0A 1A 0A` |
| TIFF | `49 49 2A 00` or `4D 4D 00 2A` |
| HEIC | ISO-BMFF `ftyp` with brand in {`heic`,`heix`,`mif1`,`msf1`} |
| DOCX | ZIP containing `[Content_Types].xml` and `word/document.xml` |
| XLSX | ZIP containing `[Content_Types].xml` and `xl/workbook.xml` |
| XML | optional UTF-8 BOM, optional whitespace, then `<?xml` or `<` + a letter, and parses as XML |

  The email path also accepts `message/rfc822` (the raw `.eml`).
- **Ledger:**
  - `sha256` and `md5` are stored as lowercase hex. Paperless-ngx 3.4.1's `original_checksum` is the **SHA-256** of the original (observed in M2), so the drift check compares the ledger `sha256`. `md5` is retained (immutable) but not used for drift, and never for security.
  - Paperless 3.4.1 accepts duplicate uploads (it only flags them), so ingest looks the SHA-256 up in Paperless first and adopts an existing document instead of uploading again.
  - Unique `(workspace_id, sha256)`.
  - No filename, subject, sender or any other content in the shared database.
- **Object store:**
  - Bucket from `SIJIL_OBJECTSTORE_BUCKET`, created with object lock and versioning.
  - Key `"{tenant_ref}/{sha256}"`.
  - Unsealed originals use mode **GOVERNANCE**. `retain_until` = provisional retention, the end of the arrival's calendar year + 10 years for `MA` (from `retention_years(country)`, with the map `{"MA": 10}` in `sijil_core.retention`).
  - Retention can only be extended. COMPLIANCE at seal is M3/M4.
- **Audit:**
  - `hash = sha256(prev_hash_bytes ‖ canonical_json(event))` as hex. `prev_hash` for the first event is `"0"*64`.
  - Canonical JSON: sorted keys, separators `(",", ":")`, `ensure_ascii=False`, UTF-8, datetimes ISO-8601 UTC with `Z`, UUIDs as strings.
  - The hashed event dict is exactly `{workspace_id, seq, at, actor_type, actor_id, action, target_type, target_id, ip, data}`.
  - `seq` starts at 1 per workspace and has no gaps.
  - The app role has no UPDATE/DELETE grant on `audit_event`, and a trigger rejects both.
- **Audit actions written in M2:**
  - `document.uploaded`, `document.duplicate_rejected`
  - `document.ingested`, `document.ingest_failed`, `document.ingest_delayed` (final-review ruling I1)
  - `document.viewed`, `documents.listed`
  - `email.received`, `email.rejected`
  - `integrity.drift`, `integrity.check_ok`
  - `member.added`, `member.role_changed`, `member.removed`, `org.require_totp_changed`, written to every workspace of the org
  - `actor_type` ∈ {`user`, `system`, `email`}
- **Inbound email:**
  - Address `{slug}.{inbound_token}@{SIJIL_INBOUND_DOMAIN}`. `inbound_token` is 10 random base32 lowercase characters, unique, created with the workspace.
  - Unknown recipient → `550 5.1.1` at RCPT.
  - Message over 100 MB → `552 5.3.4`.
  - The raw `.eml` is archived as a document, and each attachment is archived as its own document.
- **Formats Paperless 3.4.1 can't consume:**
  - The original stays in the object store and ledger (it is archived and counted).
  - `ingest_state = "unsupported"`, `ingest_error_code = "ingest.unsupported_format"`.
  - Recorded in the audit log, never retried.
- **Performance:** upload accepted (202) in < 2 s at p95 for a 10 MB file on the dev stack.

## Review Focus

1. **The same file uploaded twice at the same moment** (a double click, or web and email together) creates exactly one ledger row. The other gets 409 `document.duplicate` with the existing id. → Task 5 `test_concurrent_identical_uploads_create_one_row`.
2. **Two audit appends at once in one workspace** don't fork the chain: `seq` has no gaps and `verify` passes. → Task 4 `test_parallel_appends_keep_single_chain`.
3. **Paperless down or slow during an upload:** the upload still returns 202 in < 2 s, the original is safe in the object store, and ingest retries until Paperless returns. → Task 5 `test_upload_accepted_when_tenant_unreachable`, Task 6 `test_ingest_retries_until_paperless_returns`.
4. **A 150 MB upload** is refused with 413 as soon as the stream passes 100 MB, nothing reaches the object store or the ledger, and the server never holds the whole body in memory. → Task 5 `test_upload_rejects_over_100mb_without_storing`.
5. **A retained original deleted directly in Paperless** (bypassing our API, e.g. with the admin password) is flagged by the drift check, and an `integrity.drift` audit event is written. → Task 9 `test_drift_check_flags_missing_paperless_document`.

**Interfaces:**
- Produces:
  - `filetypes.FileKind` (StrEnum `pdf, jpeg, png, tiff, heic, docx, xlsx, xml, eml`) and `filetypes.sniff(path: Path, *, allow_eml: bool = False) -> FileKind | None`.
  - `MAX_UPLOAD_BYTES = 104_857_600`.
  - `ingest.Accepted(document_id: UUID)` and `ingest.Duplicate(document_id: UUID)`. Errors are `ingest.TooLarge`, `ingest.Unsupported` and `ingest.Empty` (the API maps them to the codes in Global Constraints).
  - `async ingest.accept_file(*, sessions: async_sessionmaker[AsyncSession], store: ObjectStore, enqueue: Callable[[UUID, UUID], Awaitable[None]], workspace: Workspace, country: str, chunks: AsyncIterator[bytes], source: DocumentSource, actor_type: ActorType, actor_id: str | None, ip: str | None, source_email_id: UUID | None = None, now: datetime, allow_eml: bool = False) -> Accepted | Duplicate`:
    1. Spool to `tempfile.SpooledTemporaryFile(max_size=8 MiB)` while updating sha256, md5 and the size. Raise `TooLarge` as soon as the size passes `MAX_UPLOAD_BYTES`.
    2. `sniff`.
    3. If a ledger row with this sha256 already exists → `Duplicate` (+ audit `document.duplicate_rejected`).
    4. `store.put_original(f"{tenant_ref}/{sha256}", …, provisional_retain_until(now.date(), country))`.
    5. `INSERT … ON CONFLICT (workspace_id, sha256) DO NOTHING RETURNING id`. No row → `Duplicate` (the content-addressed put was harmless) + audit.

**Interfaces:**
- Produces: `async ingest_document(ledger_id: UUID, *, sessions, keys: KeyService, store: ObjectStore, paperless: Callable[..., PaperlessClient], poll_timeout_s: float = 300, settings: WorkerSettings) -> None`:
  1. Load the row and the workspace (assert region; the workspace must be `active`, else a transient error so it retries later).
  2. `ingest_state=sending`.
  3. Stream the original from the store.
  4. `upload(bytes, filename=f"{sha256[:12]}.{ext}")`. The filename sent to Paperless is derived, never the user's.
  5. Poll `task` until SUCCESS → `paperless_doc_id`, `ingest_state=consumed`, audit `document.ingested` (actor system). Paperless's duplicate message → resolve by checksum lookup, and treat it as consumed if the existing document's checksum matches.
  6. Already `consumed` → no-op (idempotent redelivery).
  7. Transient errors → stay `sending`/`queued` with `ingest_error_code`, re-raised for retry. On exhaustion → `failed` + audit.
